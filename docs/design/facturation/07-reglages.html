Ce que l'écran affirme

  • Une donnée, un endroit. Nom, titre et numéro ADELI ou RPPS ne sont pas ressaisis : ils sont lus du dossier professionnel et affichés verrouillés.
  • La mention légale n'est pas un champ libre. Le praticien choisit sa situation ; le texte de la mention est fourni par l'application.
  • La numérotation se montre, elle ne se règle pas. Le prochain numéro est affiché pour rassurer ; il n'y a pas de champ pour le changer une fois la première facture émise.
  • Un enregistrement par page, avec le rappel de ce qui a changé, comme les autres pages de Mon compte.
  • L'IBAN est masqué à l'affichage ; « Modifier » redemande le mot de passe, comme les réglages de sécurité (fiche 18).

Modifications non enregistrées : TVA

Rubrique TVA de la carte (576 px), après « Enregistrer » refusé. Choisir « Assujettie à la TVA » révèle Taux et N° de TVA intracommunautaire (fiche 39, Structure 3). Un seul taux (plusieurs taux : hors périmètre). Taux : vat.rateBp en points de base, affiché en pourcentage (2000 → 20 %) ; N° : vat.vatNumber (L5.1). Le refus 422 VAT_NUMBER_REQUIRED s'affiche sous le champ ; 422 VAT_RATE_REQUIRED s'affiche de même sous Taux. Le texte d'erreur « Obligatoire pour ce régime. » n'est pas donné par la fiche : libellé neutre proposé ici. La mention de ce régime vient de l'API (vat.mention, L5.1) : son texte n'est écrit ni dans la fiche ni dans L5, il n'est donc pas dessiné ; l'aperçu détaille alors hors taxes, TVA et toutes taxes (fiche).

Modifiables tant qu'aucune facture n'est émise.

Même rubrique que dans la page, avant toute émission : numbering.locked vaut false, les deux préfixes sont des champs ordinaires, sans cadenas (fiche 39, Structure 4 ; L5.1). Le prochain numéro est numbering.nextInvoiceNumber ; aucun champ ne permet de le choisir. L5 renvoie aussi nextCreditNoteNumber, que la fiche n'affiche pas : il n'est pas dessiné. Si une première facture est émise entre-temps, 409 NUMBERING_LOCKED verrouille les préfixes (état de la page ci-dessus) avec un toast dont la fiche ne donne pas le texte.

« Modifier » sur la ligne Envoi d'une facture de la rubrique E-mails ouvre le panneau latéral partagé de 480 px : Objet, Message, variables {numéro}, {montant}, {reste dû}, {échéance} (fiche 39, Structure 7). Données : emailTemplates.invoice { subject, body } ; la ligne Relance d'une facture en retard ouvre le même panneau sur emailTemplates.reminder (objet « Rappel : facture {numéro} »). Le message reprend, variables à la place des valeurs, celui du dialogue d'envoi (04 · Facture émise). Le titre « Variables » et le pied « Annuler · Enregistrer » ne sont pas donnés par la fiche. Point ouvert : la fiche ne dit pas si ce panneau enregistre tout de suite (comme les prestations) ou alimente la barre d'enregistrement de la page ; L5 porte les modèles dans PUT /api/me/billing-settings, donc avec le reste de la page.

Mot de passe incorrect.

« Modifier » à côté de l'IBAN masqué (rubrique Règlement) ouvre ce dialogue : le nouvel IBAN et le mot de passe du compte, comme les réglages de sécurité (fiche 39, Interactions ; fiche 18). Envoi : PUT /api/me/billing-settings/iban { iban, currentPassword } → 204 (L5.1) ; la page relue n'affiche que l'IBAN masqué, jamais en clair. Ici le refus 403 PASSWORD_INVALID, sous le mot de passe. « Retirer l'IBAN » appelle DELETE sur la même route, mot de passe dans le corps (L5.1 seulement : la fiche ne prévoit pas ce geste, libellé neutre proposé ici). Libellés « Nouvel IBAN », « Mot de passe du compte », « Mot de passe incorrect. » : tirés du sens de la fiche, sans texte donné par elle. Valeurs factices.

Modifications non enregistrées : N° SIRET

Quitter la page (un autre onglet, le rail, le retour du navigateur) avec des modifications en attente ouvre le dialogue de confirmation partagé (pm-confirm-dialog : titre, description, « Annuler », bouton de confirmation, sans croix). Titre de la fiche 39 (Interactions) ; la description reprend la barre d'enregistrement ; le libellé « Quitter » est proposé ici, la fiche n'en donne pas. « Annuler » garde la page et ses saisies.

Sous 900 px

Cadre de 860 px. Le sommaire devient une rangée au-dessus du formulaire, qui défile horizontalement quand elle ne tient pas ; l'aperçu passe sous la carte (fiche 39, Structure, « Sous 900 px »). Rien d'autre ne change : mêmes rubriques, même barre d'enregistrement au pied de la carte, aperçu de 360 px.
