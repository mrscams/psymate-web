Un paiement ne se crée pas ici : il s'enregistre depuis une facture. Le menu de ligne porte « Télécharger le reçu », « Ouvrir la facture » et « Annuler le paiement » (dialogue de confirmation partagé). Un remboursement est une ligne négative, rattachée à son avoir. La barre de répartition n'emploie que la couleur de marque : la longueur porte l'information, le nom et le montant sont écrits.

Colonnes du fichier : date, numéro de facture ou d'avoir, mode, référence, montant ; le nom seulement si le praticien le demande. Le choix par défaut ne fait sortir aucun nom de patient de l'application. Le fichier est produit par l'API, comme les exports de dossier (fiche 19).

Ce que l'écran affirme

  • Le journal ne se retouche pas. On n'y modifie pas un montant : on annule le paiement et on en saisit un autre ; les deux gestes restent visibles.
  • Les totaux viennent du serveur. Total de la période et répartition par mode sont servis avec la page, pas additionnés sur les lignes affichées (la liste est paginée).
  • Le secret par défaut. L'export sans nom est le choix présélectionné ; le nom complet est un choix explicite, expliqué.
  • Mobile. Cartes d'une ligne (date, patient, mode, montant), total en tête, export dans le menu.

Sous 600 px (fiche 37, Structure 6) : le total en tête, puis la période et l'étendue ; les modes dans une liste (champ « Mode de paiement », valeur « Tous », mêmes choix que le groupe de bureau, « Autre » compris s'il existe) ; une carte d'une ligne par paiement (date, patient, mode, montant), qui ouvre la facture ; « Exporter le journal » dans le menu de la barre (à droite), qui ouvre le même dialogue d'export.
