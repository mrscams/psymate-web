4. Erreurs

toutes issues de application/problem+json (RFC 9457) : status, code, errors[{field, code, message}], retryAfterSeconds
422 · Validation champ par champ · fiche patient (16)
2 champs à corriger. Nom affiché · Date de naissance
Le nom affiché est obligatoire.
La date de naissance ne peut pas être dans le futur.
Les champs valides gardent leur saisie.
Réponse reçue 
{
  "status": 422,
  "code": "VALIDATION_FAILED",
  "errors": [
    { "field": "displayName", "message": "Le nom affiché est obligatoire." },
    { "field": "birthDate", "message": "La date de naissance ne peut pas être dans le futur." }
  ]
}

Le résumé reçoit le focus à la soumission ; chaque lien mène au champ. Message sous le champ fautif, bordure #9A2F22, aria-invalid + aria-describedby. Le module patients ne renvoie pas de code de champ : on affiche message tel quel ; ailleurs (entrées, liens, identité) le code de champ sert au test, jamais à l'affichage.

Avertissement, pas erreur : le compte est sain, une action du praticien suffit. Page dédiée : 25 Confirmation d'e-mail.

Aucune donnée patient n'est affichée après ce message ; la fiche 27 prend le relais (G Q26, M1-14b).

409 · LINK_EXISTS · éditeur de lien (06)
Ce lien existe déjà · Modifier le type ? « Surcharge au travail » est déjà liée à « Insomnie, 3 nuits » comme cause probable (lien praticien du 12 oct.). Un seul lien par paire d'entrées.

Le conflit propose toujours la sortie la plus courte ; la saisie du panneau reste intacte.

423 · ACCOUNT_LOCKED · connexion (11)
Trop de tentatives 5 mots de passe faux pour cet e-mail. Nouvel essai possible dans 14 min 32 s. Mot de passe oublié ? · Retry-After: 872

Compte à rebours depuis retryAfterSeconds, annoncé toutes les minutes seulement (aria-live="polite"). Le bouton se réactive à zéro.

429 · RATE_LIMITED
Trop de requêtes, réessayez dans 12 s. Votre saisie est conservée. Retry-After: 12

Limite de 600 requêtes par minute et par session (G Q24). Le client rejoue la requête à la fin du délai, sans action de l'utilisateur.

Hors ligne · aucune réponse réseau

Bandeau fixé sous la barre d'application, sur tous les écrans ; disparaît seul au retour du réseau avec le toast « Connexion rétablie · 2 brouillons envoyés ».

500 · erreur inattendue

Jamais de trace technique à l'écran : seul l'identifiant (en-tête X-Request-Id) en JetBrains Mono.

Règles
  • Le panneau est le même sur tous les écrans ; les lignes sans objet pour l'écran courant sont grisées (#8A94A6) et annoncées « indisponible ici ».
  • Chaque bouton qui a un raccourci l'affiche en JetBrains Mono à droite de son libellé (« Nouveau patient N »), comme dans les fiches 01 et 02.
  • À la première connexion, « Voir les raccourcis » accompagne le bloc « Créez votre premier patient » (section 2) ; après la première entrée, le lien passe dans le menu du compte.

Hors de cette planche : mode sombre (étude §8) et déclinaison mobile. Cette planche fait autorité pour la forme des trois états et des notifications.
